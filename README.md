# Бот для MAX: ответы по документам + веб-админка

Бот отвечает в мессенджере MAX на вопросы по энергетике. Ответы берёт из ваших документов (папка `docs`)
и из базы «вопрос-ответ», которую вы наполняете в веб-админке. Языковая модель подключается через API
(OpenRouter или Yandex Cloud).

## Что делает каждый файл

| Файл | Для чего нужен |
|---|---|
| `bot.py` | Главный файл, запускается командой `python bot.py`. Принимает сообщения из MAX, ищет подходящие куски документов, отправляет вопрос с найденным контекстом в языковую модель, возвращает ответ. Содержит системный промпт (правила: отвечать только по энергетике), команды `/start`, `/reset`, `/docs`, `/reload`, учёт неизвестных вопросов и режим «только по контексту». |
| `rag.py` | «Библиотекарь» бота. Читает документы (PDF, DOCX, TXT, MD), режет их на фрагменты, строит поисковый индекс (алгоритм BM25) и по вопросу находит самые подходящие фрагменты. Также хранит и ищет пары «вопрос-ответ». RAG = «поиск по документам + ответ модели». |
| `admin.py` | Веб-админка (запускается вместе с ботом). Разделы: кнопка «Переобучить», режим ответов, неизвестные вопросы, пары «вопрос-ответ», загрузка документов, последние вопросы к боту, статистика. |
| `qa_test.py` | QA-тест. Запускает много «пользователей» одновременно с разными вопросами (по теме, не по теме, попытки обойти правила, граничные случаи) и пишет отчёт в папку `qa_reports`. Ваши данные не меняет. |
| `requirements.txt` | Список библиотек Python, которые нужно установить: `pip install -r requirements.txt`. |
| `.env.example` | Образец файла настроек. Его нужно скопировать в `.env` и вписать свои токен и ключ. |
| `docs/` | Папка с документами, по которым отвечает бот (7 справочных текстов по темам энергетики). Сюда же кладите свои PDF, DOCX, TXT, MD. |

## Файлы, которых нет в архиве (их создаёте вы или программа)

| Файл или папка | Откуда берётся |
|---|---|
| `.env` | Создаёте вы: копия `.env.example` с вашими токеном MAX и ключом модели. Никому не отправляйте. |
| `.venv/` | Виртуальное окружение с установленными библиотеками (у вас уже есть). Не удаляйте. |
| `qa.json` | Появляется, когда вы добавляете пары «вопрос-ответ» в админке. |
| `unknown.json` | Список неизвестных вопросов (создаётся ботом). |
| `settings.json` | Переключатель режима ответов из админки. |
| `qa_reports/` | Отчёты QA-теста (создаётся при запуске `qa_test.py`). |

## Как обновить свой проект

1. Распакуйте архив.
2. Скопируйте файлы `bot.py`, `rag.py`, `admin.py`, `qa_test.py`, `requirements.txt`, `.env.example` и папку `docs` в свою папку бота (например, `bot max`) с заменой. Файл `.env` и папку `.venv` не трогайте.
3. В терминале VS Code (там, где виден `(.venv)`): `pip install -r requirements.txt`.
4. В `.env` добавьте (если ещё нет): `LLM_MODEL=...`, `ADMIN_PASSWORD=ваш_пароль`.
5. Запустите: `python bot.py`. Админка откроется по адресу http://localhost:8080 (логин `admin`, пароль из `.env`).

## Подключение GigaChat вместо OpenRouter

1. В личном кабинете GigaChat API (developers.sber.ru) скопируйте «Авторизационные данные» (ключ авторизации).
2. Скачайте сертификат «Russian Trusted Root CA» на сайте Госуслуг (gosuslugi.ru/crt) и запомните путь к файлу.
3. `pip install gigachat` (или `pip install -r requirements.txt`).
4. В `.env` закомментируйте блок OpenRouter и добавьте:
   ```
   LLM_PROVIDER=gigachat
   GIGACHAT_CREDENTIALS=ваш_ключ_авторизации
   GIGACHAT_SCOPE=GIGACHAT_API_PERS
   GIGACHAT_MODEL=GigaChat-2
   GIGACHAT_CA_BUNDLE_FILE=C:/путь/к/Russian_Trusted_Root_CA.cer
   ```
   Для быстрой проверки вместо сертификата можно временно указать `GIGACHAT_VERIFY_SSL_CERTS=false` (небезопасно).
5. Перезапустите бота. Если модель с таким названием недоступна, список доступных имён можно посмотреть в документации GigaChat.

## Как пользоваться

- Пишите боту в MAX обычными вопросами словами из документов. В конце ответа «📎 Искал в: …» показывает источник.
- Бот ответил плохо: в админке найдите вопрос в «Последние вопросы», нажмите «Исправить», впишите правильный ответ, нажмите «Добавить пару», затем «Переобучить». Новая база начинает работать сразу. Это не переобучение самой модели, а обновление базы знаний.
- Новые документы: загрузите их в админке (или положите в `docs`) и нажмите «Переобучить» (или отправьте боту `/reload`).
- Вопросы не по теме и вопросы, на которые нет ответа в базе, собираются в разделе «Неизвестные вопросы».
- Режим «только по контексту» (переключатель в админке): бот отвечает только по документам и парам, ничего не придумывая.

## QA-тест

```
python qa_test.py --fake                    # проверка логики бота с имитацией модели, лимиты не тратятся
python qa_test.py --users 5 --per-user 3    # настоящая модель (расходует лимиты OpenRouter!)
```
Отчёт: `qa_reports/qa_report.md` и `qa_reports/qa_results.csv`. Режим `--fake` проверяет логику бота,
а не качество настоящей модели.

## Команды бота в MAX

`/start` приветствие · `/docs` список документов · `/reload` перечитать документы и пары · `/reset` очистить память диалога

## Если что-то не работает

- `KeyError: 'MAX_BOT_TOKEN'` — файл `.env` не найден: он должен называться именно `.env` и лежать рядом с `bot.py`.
- `ModuleNotFoundError` — не выполнен `pip install -r requirements.txt` или выбрано не то окружение (слева в терминале должно быть `(.venv)`).
- `402 Insufficient Balance` — на счёте провайдера модели нет средств.
- `404` от модели — модель отключили, выберите другую в `LLM_MODEL`.
- `429` — исчерпан лимит запросов.
- Пустой ответ или обрыв — смените модель на «не думающую» или увеличьте `MAX_TOKENS`.
